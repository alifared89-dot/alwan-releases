# 2026-10-16 — Infinix device-media revision contract repair

## Incident
Published media manifest v17 contained 169 entries and 71 immutable ZIP chunks. Two revision strings contained spaces; the Android validator requires [A-Za-z0-9._-]+. Validation rejects the entire manifest before activation, preventing updates of the missing image archives.

Affected devices:
- dev_xzhg7ypmflf45ybmhrhl7zlthq: infinix-user-reviewed-note 3-frontback-v1 -> infinix-user-reviewed-note-3-frontback-v1
- dev_jmdbgi7l4rqfu473yzootd7jey: infinix-user-reviewed-zero 4 plus-frontback-v1 -> infinix-user-reviewed-zero-4-plus-frontback-v1

## Root cause
The publishing integrity script did not validate revision-token syntax against the Android client contract. The normal bot.py publishing generator already uses sanitized model codes. The 79-image reviewed batch used user-reviewed tokens; the exact external staging script that created the invalid strings is not proven from repository history. The confirmed root cause is inadequate pre-publication validation across publishing routes.

## Controlled repair
This change advances the manifest to v18, fixes exactly two revision identifiers and updates the manifest descriptor hash. The pinned migration exception permits ONLY those exact identity renames with other record fields identical. Images, hashes, ZIPs, chunk descriptors, source evidence, licenses, catalog, schema, and APK remain unchanged.

## Prevention and follow-up
All publishing routes, including Termux-reviewed batches, must run strict verify_media.py client-contract validation; invalid revisions now fail CI. Keep the narrowly scoped migration guard test. Never bypass branch protection or weaken the Android validator. After protected merge, re-check the phone; log and address any independent failures.
